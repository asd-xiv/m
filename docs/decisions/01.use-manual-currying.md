# 01. Use internally manual currying over `curry()` primitive

**Date**: 2026-03-06

**Problem**:

- Using the `curry()` primitive for library functions creates unnecessary
  closures and makes it impossible to handle ambiguous first arguments
- When the first param can be a matcher object, a default value, or an optional
  direction string, `curry()` just counts params, it can't know what was passed
  and decide the execution path. The `pipe` halts waiting for the next param

**Solution**:

- Manual `params.length` branching with `// @signature` comments
- Each branch is explicit, creates minimal closures, and can inspect argument
  types when needed (e.g., `sort` detecting whether the first arg is a direction
  or an array)

```ts
// Manual branching
const sort = ((...params: unknown[]) => {
  // @signature (input)
  if (Array.isArray(params[0])) {
    return _sort("asc", params[0])
  }
  // @signature (direction) => (input)
  if (params.length === 1) {
    return (input: unknown[]) => _sort(params[0], input)
  }
  // @signature (direction, input)
  return _sort(params[0], params[1])
}) as SortFn
```
