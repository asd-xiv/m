# 02. Add runtime type checks at function boundaries

**Date**: 2026-03-06

**Problem**:

- Debugging a `pipe` can be hell. When a function receives wrong input mid-pipe,
  the error surfaces as `cannot read property of undefined`, useless to pinpoint
  what step broke
- **API responses**, **user input**, **event payloads**, **JSON parsing**, all
  bypass TS at runtime

**Solution**:

- Every public-facing function throws `TypeError` with the function name when
  input doesn't match expected types
- Where the check lives depends on the parameter's position stability:
  - **Fixed-position params** (matcher, config, direction) - always `params[0]`,
    validate in the main body
  - **Variable-position params** (input) - position shifts between curried and
    uncurried. Validate in `_fn` helper, it's the convergence point of all
    signatures where positions are known

**Acknowledgments**:

- The check is a single `typeof` / `Array.isArray` / `isPlainObject` —
  negligible cost vs the operation itself
