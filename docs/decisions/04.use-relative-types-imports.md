# 04. Use relative imports for `../../types/` instead of `@t/` path alias

**Date**: 2026-03-16

**Independent facts**:

- TypeScript `paths` aliases are a type-checker convenience only — the compiler
  never rewrites them in emitted `.d.ts` output
- With `skipLibCheck: true` (standard in every downstream project) a broken
  import is silently swallowed: every type that flows through it becomes `any`
- `tsc-alias` is the conventional post-process workaround but it is unmaintained

**Problem**:

- A consumer resolving `@asd14/m` through its published declarations has no
  `@t/*` mapping. No error is shown, but inference breaks at the call site
- Concretely: `Morphism` from `@t/function.js` became `any`, poisoning
  `MapMorphism<I, O>` so that `map(f => ..., readonlyArray)` inferred `f: any`
  in consumers

**Solution**:

- Import from `types/` with explicit relative paths in every source file
  (`../../types/function.js`, `../../../types/object.js`, etc.)
- Emitted `.d.ts` files now contain resolvable relative paths that any consumer
  can follow without configuration
