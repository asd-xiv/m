# 05. Read an array in a function slot as a pipe

**Date**: 2026-11-25

**Independent facts**:

- TypeScript types an array literal argument after it infers the other
  arguments, eg. the item type from `items`
- TypeScript resolves an inline generic call, eg. `pipe(...)`, on its own,
  before it knows that type

**Problem**:

- An inline `pipe()` loses the item type: in
  `partition(pipe(item => item.id, id => id > 0), items)`, `item` is `unknown`,
  and `filter(pipe(read("id"), isEqual(1)), items)` does not type-check
- In a patcher or a matcher, an array is also a value, so `{ tags: ["x"] }`
  type-checked as a value and threw at runtime as a pipe

**Solution**:

- Every function slot reads an array as a pipe:
  `filter([read("id"), isEqual(1)], items)`
- A plain value in a patcher or a matcher is never an array. Set an array with
  `() => ["x"]`, match one with a predicate
- Check each function of the array once, and name the caller in the error:
  `@asd14/m/filter: expected 'fn[1]' to be 'Function', got 'String'`

**Rejected**:

- A key marker for a pipe, eg. `"tags |>"`: it splits the rule by slot, and a
  typo fails silently in JS. A minor release can still add it

**Acknowledgments**:

- A pipe array is not a function. It works only where an m function takes it.
  Name a chain to reuse elsewhere with `pipe(...)`
